# Ван-Шот — движок для настольных RPG one-shot'ов

Веб-инструмент для проведения одиночных партий (one-shot) настольных RPG
онлайн: у Мастера и Игроков — раздельные интерфейсы в браузере, общее
состояние синхронизируется в реальном времени через WebSocket.

## Возможности

- **Карта**: перемещение токенов персонажей и NPC, туман войны (у игроков — «живой»: мягкие края с колышущейся
  холодной дымкой; личный выключатель в блоке «Эффекты»), картинки локаций, свободное рисование, подсветка клеток,
  достижимых за ход. Зум колесом до ×12 (фишка вплотную). Горячие клавиши: **туман** — X («Скрыть»/«Открыть»), Shift
  (пока зажат — наоборот), `[` `]` или Ctrl+колесо — размер кисти; **рисунок** — X (перо/ластик), Ctrl+Z (отменить),
  `[` `]` или Ctrl+колесо — толщина.
- **Персонажи и NPC**: листы персонажей (атрибуты/навыки/инвентарь), HP/
  энергия/решимость/броня, коды доступа для входа игроков. У мастера заметки героя и NPC (и «Секрет» NPC)
  всплывают при наведении на фишку на карте или на карточку справа; править — в окне «Инфо».
- **Бой**: инициатива, индикатор текущего хода, анимация начала боя.
- **Кубики**: броски с логом и анимацией на обеих сторонах.
- **Картинки на карте**: загрузка и вставка из буфера, слои, поворот, отражение, **обрезка**, растяжение в одну сторону,
  **дубликат**; горячие клавиши — Ctrl+D (дубликат), Delete (удалить), C (обрезка), Shift при перетаскивании угла
  (растянуть как угодно). Игрок правит так же свои картинки (после согласия мастера).
- **Чат**, **саундборд и музыка**, **спецэффекты** на карте (дым/огонь/
  фейерверк), **погода** на экране.
- **Масштаб интерфейса** 70–150% (пункт «Вид» у мастера и у игроков, личная настройка устройства; карта не
  масштабируется).
- **Ролики**: мастер загружает короткие видео (mp4/webm до 25 МБ) в пункте «Ролики» и запускает их — у всех
  игроков и у него самого открывается мини-окно с рамкой, ролик идёт автоматически; остановка закрывает окно у всех,
  музыка на время ролика приглушается.
- **Не привязан к игре**: название, тема, звуки, подписи, навыки и параметры проверок мастер меняет в интерфейсе
  (раздел «Своя игра» ниже).
- Состояние партии переживает перезапуск сервера (`server/data/runtime.json`).

## Стек

- Сервер: Node.js + Express + Socket.IO (`server/`).
- Клиент: гибрид — обычные `<script>`-скрипты (`public/js/`) для сокета и
  канваса карты, плюс два независимых Vue 3 приложения (`src/gm-panel/`,
  `src/player-panel/`), собираемые Vite в `public/dist/`.

## Запуск

```bash
npm install
npm start
```

`npm start` пересобирает оба Vue-бандла и запускает сервер с `--watch`
(автоперезапуск при изменении серверных файлов). По умолчанию сервер
поднимается на `http://localhost:3000` — Мастер заходит на `/gm.html`,
Игроки — на `/player.html` (или на `/`, см. `server/index.js`).

Другие команды:

```bash
npm run build   # только сборка Vue-бандлов, без запуска сервера
npm run dev     # vite dev-сервер (для разработки Vue-компонентов)
```

## Docker

```bash
docker compose up -d --build   # сборка образа и запуск (порт 3000 внутри, 127.0.0.1:3002 снаружи)
```

В образ при сборке попадают `server/` (без `server/data`) и `public/`, на диск хоста вынесена только папка `data/`
(`./data:/app/server/data`). Поэтому **всё, что меняется в игре, лежит в `data/`** и переживает
пересборку и пересоздание контейнера: состояние партии (`runtime.json`), настройки игры (`game.json`), герои, NPC,
навыки и локации, герои с правками (`roster.json`), загруженные в игре картинки, аватары, музыка, звуки и ролики
(`data/uploads/…`), добавленные ГМ списки музыки и звуков (`audio-library.json`) и роликов (`video-library.json`).

**Чистая `data/` не ломает запуск:** сервер сам создаёт недостающие файлы из примера игры (`server/defaults/`) —
сначала движок стартует с примером, дальше мастер всё перестраивает под свою игру. Другая игра = другая папка `data/`.

Обновление: `git pull`, затем `docker compose up -d --build` (`docker compose restart` образ не обновляет).

## Своя игра

Название, оформление, звуки, подписи, навыки и параметры проверок меняются **из интерфейса мастера** — пункт
«Игра» в левой панели, без правки кода и пересборки образа:

- **Оформление** — название и подзаголовок игры (заголовок формы входа), четыре цвета интерфейса;
- **Звуки** — звуки броска кубика, начала боя и заставки локации, показ примеров из образа (музыка, звуки,
  готовые аватары), свои готовые картинки героев;
- **Подписи** — как называются атрибуты, ресурсы и фракции (и иконки к ним), что видят игроки вместо имени скрытого
  NPC, каталог навыков; героев, NPC и локации правят в их панелях;
- **Проверки** — кубик (d4…d20), критические значения, цена и размер бонуса за ресурс, атрибут инициативы,
  пресеты сложности, кубики урона. Механика прежняя: кубик + атрибут против сложности.

Идентификаторы и число атрибутов (три), ресурсов (HP, ход, ресурс бонуса, броня) и фракций (три) — часть движка;
меняются подписи, иконки и цвета. Для новой игры обычно достаточно: выключить «Показывать примеры из образа»,
переименовать атрибуты и ресурсы, загрузить свою музыку и картинки героев, завести героев и NPC.
Свои готовые картинки героев можно и просто положить в `data/presets/` на хосте (имена — латиница, цифры, `-`, `_`;
форматы svg, png, jpg, webp, gif) — они появятся в выборе после обновления страницы.

## Структура

```
server/     — Express + Socket.IO, вся модель состояния игры
  index.js      — обработчики socket-событий
  gameState.js  — состояние и функции-мутаторы
  map.js        — сетка, поиск пути, достижимость
  gameConfig.js — настройки игры (название, тема, подписи, проверки): проверка, слияние, хранение
  config.js     — лимиты и константы
  defaults/     — пример игры (герои, NPC, навыки, локации, настройки): в git и в образе,
                  из него засевается пустая data/
  data/         — всё изменяемое, в git не попадает: данные партии (герои, NPC, навыки, рантайм-снимок),
                  game.json (настройки игры), uploads/ (загруженное в игре), presets/ (свои готовые картинки героев)
public/     — статика клиента
  js/           — legacy-скрипты (сокет, канвас карты, drag&drop панелей)
  css/          — стили
  dist/         — собранные Vue-бандлы (генерируются, не редактируются руками)
  gm.html / player.html — точки входа
src/        — исходники Vue-компонентов
  gm-panel/      — панели интерфейса Мастера
  player-panel/  — панели интерфейса Игрока
```

Подробная архитектурная карта проекта — в `CLAUDE.md` (на уровень выше,
рядом с `content/` — папкой игрового контента, которая не входит в этот
репозиторий).
